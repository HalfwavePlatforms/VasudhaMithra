1. SYSTEM CONTEXT & PROBLEM STATEMENT
--------------------------------------------------------------------------------
You are an expert Principal Frontend Engineer building the UI for "VasudhaMithra", an AI-powered national land record digitization, verification, and cadastral intelligence system for the Digital India Land Records Modernization Programme (DILRMP).

The system ingests scanned/photographed historical land records (Pahani, Khasra, Form XII Mutation Registers in regional Indian scripts like Kannada, Hindi, Telugu), runs optical character recognition (OCR), extracts structured key-value pairs (Survey No., Khata No., Owner Name, Plot Area), evaluates them against business logic rules, calculates spatial area deltas against cadastral GIS parcel polygons, and surfaces discrepancies to revenue officers via a Human-in-the-Loop (HITL) interface.

CRITICAL DIRECTIVE (STRICT NO DATA SUPPRESSION RULE):
- DO NOT suppress, omit, mask, or truncate any field, object property, confidence metric, or spatial delta in the UI.
- DO NOT use generic placeholder text (e.g., "Lorem Ipsum" or "Field 1") or mock fallback objects that drop API attributes.
- DO NOT alter the underlying data schema of the problem statement.
- ALL fields returned by the OCR, extraction, GIS, and audit log endpoints MUST be fully visible, editable (where appropriate), and visually categorized according to risk level and confidence thresholds.

2. DUAL FRONT-END APPLICATION BREAKDOWN
--------------------------------------------------------------------------------

APPLICATION 1: Upload & Human-in-the-Loop Review Portal (Port 3000)
--------------------------------------------------------------------------------
Purpose: Primary operational portal for revenue officers and data entry clerks to upload land documents, inspect side-by-side OCR bounding boxes, verify automated field extraction, audit GIS boundary overlays, and issue official validation decisions.

Core Workspaces & Views:

A. Document Ingestion & Drag-and-Drop Uploader
   - File drag-and-drop zone supporting PNG, JPG, WEBP, and multi-page PDF documents.
   - Language selector dropdown (Kannada, Hindi, Telugu, Tamil, English, Auto-detect).
   - Document Type hint selector (Record of Rights / RTC Pahani, Khasra Extract, Mutation Register Form XII).
   - Instant upload triggering `/records/upload` API gateway call.

B. Side-by-Side Verification Workspace
   - Split Layout: Left side displays high-resolution original document viewer; Right side displays extracted fields, confidence metrics, and rule validations.
   - Bounding Box Layer: Interactive canvas overlay mapping bounding box coordinates (`[ymin, xmin, ymax, xmax]`) directly onto the scanned image with color-coded confidence halos (Green >90%, Amber 70-90%, Red <70%).
   - Raw Text Drawer: Collapsible panel showing unformatted raw OCR output text with search highlight.

C. Extracted Field Verification & Correction Grid
   - Displays all extracted fields:
     * Survey Number (e.g., "142/3B")
     * Khata Number (e.g., "891-A")
     * Khasra Number
     * Owner Name & Relation (e.g., "Ramesh Kumar S/o Shankaran")
     * Extracted Extent / Area in Acres (e.g., "2.45")
     * District, Tehsil/Taluk, Village
     * Land Classification (Dry Agricultural, Wet Agricultural, Residential, Commercial)
     * Tax Assessment Amount
   - Field Confidence Heatmap: Per-field numerical confidence badge (e.g., 99.2%). Fields with confidence below 85% must auto-expand with warning badges.
   - Inline Editing: Full inline input fields allowing the revenue officer to overwrite incorrect OCR values.

D. GIS Cadastral Overlay & Spatial Discrepancy Analyzer
   - GeoJSON Polygon Viewer: Displays the cadastral parcel boundary fetched from GIS API (`/gis/parcel/{survey_number}`).
   - Area Delta Calculator: Displays Document Extent (Acres) vs GIS Parcel Extent (Acres) side-by-side.
   - Spatial Delta Percentage (`spatial_delta_pct`): Explicit percentage difference calculation `|Doc_Area - GIS_Area| / Doc_Area * 100`.
   - Discrepancy Rule Flags:
     * If Spatial Delta <= 5%: Status `MATCH` (Green badge).
     * If Spatial Delta > 5%: Status `DISCREPANCY` (High-risk Red alert badge).

E. Validation & Approval Decision Controls
   - Violation Summary Box: Explicit list of triggered validation rules (e.g., "Deed extent differs by 23.1% from Cadastral GIS parcel").
   - Action Buttons:
     * [APPROVED / CERTIFIED] - Submits `PATCH /records/{record_id}` with `decision: "APPROVED"`.
     * [FLAG FOR FIELD SURVEY] - Submits `PATCH /records/{record_id}` with `decision: "NEEDS_SURVEY"`.
     * [REJECT RECORD] - Submits `PATCH /records/{record_id}` with `decision: "REJECTED"`.
   - Reviewer Notes Textarea: Required input for officer justification before finalizing.

F. Seeded Real Records (Pre-loaded Dataset Support)
   - Pre-loaded test cases representing actual Indian land record formats:
     1. Karnataka Bhoomi Pahani (RTC Form 16) - Survey 142/3B, Medak
     2. MP Bhulekh Khasra (Form 12) - Survey 88/B, Indore (High spatial discrepancy test case)
     3. Handwritten Mutation Register (Form XII) - Survey 77/4C, Dharwad (Medium confidence test case)


APPLICATION 2: National Intelligence & Cadastral Analytics Dashboard (Port 3001)
--------------------------------------------------------------------------------
Purpose: Executive monitoring console for district collectors and survey directors to track digitization progress, accuracy metrics, spatial discrepancy rates, and audit trails across revenue divisions.

Core Components & Layout:

A. Government Header & Live Polling Status
   - Header with Digital India Land Records Modernization Programme (DILRMP) branding.
   - Live Polling indicator (Auto-refreshes `/dashboard/stats` every 6 seconds).
   - Direct link navigation button to the Upload & Review Portal.

B. Top-Level KPI Summary Cards (5-Column Grid)
   1. Total Digitized Records (`stats.total_processed`)
   2. Certified & Validated Records (`stats.verified_count` + conversion rate %)
   3. Pending Officer Review Backlog (`stats.pending_review_count`)
   4. Spatial Discrepancies Count (`stats.spatial_discrepancy_count`, Deed vs GIS conflict >5%, with Red Alert highlight if > 0)
   5. Avg. Extraction Accuracy (`stats.avg_extraction_accuracy * 100`%)

C. Analytics & Distribution Charts (2-Column Grid)
   1. Digitization by Revenue District:
      - Progress bar breakdown by district (e.g., Bhopal, Indore, Dharwad, Medak).
      - Visual percentage fill and total record count per district.
   2. Land Classification & Document Categories:
      - Split tables mapping record counts across Agricultural vs Residential vs Commercial land classifications, and RTC vs Khasra vs Form XII document types.

D. Live Tamper-Evident Audit Trail Ledger
   - Real-time polling event log fetching `/dashboard/audit-trail`.
   - Columns: Timestamp (UTC), Action Badge (ingestion, ocr_extracted, spatial_validated, human_reviewed), Actor / Role (e.g., "Revenue Officer", "System"), Record ID, and Raw JSON Audit Details payload.
